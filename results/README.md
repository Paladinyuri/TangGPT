# 实验结果

三组实验使用相同的数据、tokenizer、等效 batch size 128、随机种子 42、学习率计划和 20,000 个 optimizer steps。

| 实验 | 参数量 | Dropout | 最佳 step | 最佳验证 loss | 最终训练 loss | 最终验证 loss |
|---|---:|---:|---:|---:|---:|---:|
| A | 12.19M | 0.0 | 2,500 | 3.9929 | 0.2084 | 8.7753 |
| B | 12.19M | 0.1 | 4,750 | 3.8249 | 2.1493 | 4.3058 |
| C | 29.37M | 0.1 | 3,250 | 3.8017 | 0.8921 | 5.4562 |

![三组实验曲线](experiment_overview.png)

## 观察

- A 与 B 只改变 Dropout。加入 `dropout=0.1` 后，最佳验证 loss 从 3.9929 降至 3.8249，最佳点也从 2,500 步推迟到 4,750 步。
- B 与 C 只改变模型规模。C 的 29.37M 参数模型取得最低验证 loss 3.8017，但相对 B 只改善 0.0232，后期过拟合反而更明显。
- 三组实验训练到 20,000 步都偏长。生成时应使用验证集最优的 `best.pt`，而不是最后一步的 `last.pt`。
- 如果只看最低验证 loss，选择 C；如果同时考虑模型体积、训练速度和泛化，B 更均衡。

原始 checkpoint 和训练日志没有提交到 GitHub。`summary.csv` 保存了用于复核的核心指标，曲线可以通过 `scripts/plot_experiments.py` 从 `train.jsonl` 重新生成。
